Algorithmic Trading Competition

> Asynchronous trading strategies, ETF arbitrage, and risk-controlled execution

Project Overview

Built a fully automated algorithmic trading system for Notre Dame DELTA's Algorithmic Trading Competition. The system traded in a live simulated market with the goal of maximizing net profit while accounting for transaction costs, volatility, exchange limits, and execution risk.

The competition market included three stocks — XYZ, ABC, and DEF — along with an ETF composed of a weighted basket of the three underlying assets. My team finished 7th out of 14 teams.

Trading Strategies

The system implemented multiple automated strategies designed for different market conditions.

  • Mean reversion using rolling mid-price averages and deviation thresholds
  • Tiered long and short position sizing based on signal strength
  • ETF arbitrage using the weighted fair value of the underlying basket
  • Concurrent execution of ETF and hedge legs to reduce directional exposure
  • Dynamic trade sizing based on notional exposure limits

System Architecture

The trading engine was built in Python using an asynchronous, event-driven architecture. Market data, strategy evaluation, and order execution could run concurrently without blocking one another.

  • Async/await architecture for low-latency execution
  • REST-based market data retrieval using HTTP requests
  • Real-time bid/ask, order book, and recent trade processing
  • Modular strategy classes for independent trading logic
  • Retry and timeout handling for market-data reliability

Risk Management

The system was designed around strict exchange constraints rather than pure signal generation. Strategy logic accounted for position limits, gross exposure, fees, slippage, rate limits, and the need to complete multi-leg hedges quickly.

  • Per-trade notional exposure caps
  • Exchange position and gross exposure limits
  • Maker/taker fees and transaction costs
  • Rate-limit and cancel-ratio awareness
  • Aggressive execution when hedge completion was more important than price improvement

Purpose

This project provided hands-on experience building a real-time automated system where statistical signals, software reliability, execution quality, and risk controls all had to work together under competition constraints.
